# Privacy & Security

Privacy is a core product promise, not an afterthought. Subby is designed and
verified to keep your data on your device.

## Privacy guarantees

- **No analytics, telemetry, or tracking.** There are no tracking SDKs and no
  usage reporting anywhere in the code.
- **No network.** No accounts, no cloud sync, and no outbound requests of any
  kind. The app is fully functional offline — including desktop notifications,
  which are delivered locally by the OS.
- **Local-only storage.** All data is stored as JSON files in the local
  application data directory (or a folder you choose). Nothing leaves your
  machine.

These are enforced and continuously verified — see "Verification" below.

## Exchange rates (bundled, offline)

Exchange rates ship with the app as a **bundled, read-only FX snapshot** — there
is no live request for rates. The dataset is **European Central Bank (ECB) euro
foreign exchange reference rates, as of Oct 1, 2026**, stored at
`resources/fx-snapshot.json`:

- **Offline and read-only.** The snapshot is loaded from the app's bundled
  `resources/` directory through a main-process resource reader using only
  `node:fs` — no network, and the file is never written back.
- **Dated.** It carries its own `asOf` date (`2026-10-01`) and a schema version,
  so a surface can show "rates as of {date}" and a corrupt/unknown-version bundle
  fails loudly rather than producing a silently wrong total.
- **ECB attribution** is shown in the About screen.

The opt-in online rate *refresh* (which would update rates from the network) is
a separate, explicitly opt-in feature and is off by default.

## Brand logos (bundled Logo Pack, offline)

Subscription rows show a small brand-logo tile. By default this is served
entirely offline from a **bundled, read-only Logo Pack** — there is no live
request for logos, so the logo surface works with **zero network** out of the
box:

- **Curated Simple Icons subset (CC0).** The pack is a curated subset (~200
  common streaming / music / software / cloud / gaming / finance brands) of
  [Simple Icons](https://simpleicons.org), which are published under the
  **CC0 1.0 Universal** public-domain dedication. The full ~3,400-icon catalog
  is deliberately **not** shipped — Subby ships only the curated subset to keep
  the install light. The logos are brand trademarks of their respective owners.
- **Generated at author time, never shipped as a dependency.** The pack lives at
  `resources/logo-pack.json`, generated by the devtime script
  `scripts/generate-logo-pack.mjs` (run via `npm run logopack:generate`). The
  `simple-icons` package is a **devDependency only** — it is never imported by
  shipped source and never bundled into the app; the shipped code reads only the
  generated JSON through the same main-process resource reader as the FX snapshot.
- **Offline and read-only.** The pack is loaded once at launch through a
  main-process resource reader using only `node:fs` — no network, and the file is
  never written back. A missing or corrupt pack degrades silently: every row
  simply shows a deterministic lettered/colored fallback tile.
- **Deterministic lettered fallback.** Any brand not in the pack (and every brand
  if the pack fails to load) renders a lettered tile derived from the
  subscription name — never blank, never a blocking fetch.

**Removing a brand.** Simple Icons honors brand-removal requests, and Subby
provides a matching removal path. The **durable** removal is to delete the
brand's line from the curated list in `scripts/generate-logo-pack.mjs` and re-run
`npm run logopack:generate` — the curated list is the source of truth. Deleting
the brand's entry from `resources/logo-pack.json` alone is only **transient**:
the next `npm run logopack:generate` re-adds it from the curated list.

Rows for a removed brand fall back to the lettered tile automatically.

The opt-in online *live logo fetch* (which would fetch a brand's favicon from the
network for brands not in the bundled pack) is a separate, explicitly opt-in
feature and is off by default.

**Live logo fetch — provider of record and fallback-of-record.** When — and only
when — you turn **Live logo fetch** on, a bundled+cache *miss* for a real domain
is fetched from a single provider of record: **Google's favicon service** (host
`t2.gstatic.com`, path `/faviconV2`). That request sends the service's domain (not
your identity or any subscription detail) to Google; over time, the aggregate set
of domains you fetch reveals the full set of services you track to Google, linked
to your IP address — which is exactly what the enable notice states before you
turn it on. A **successfully** fetched logo is cached locally and **not
re-fetched**. A fetch that fails to produce a usable logo (a 404, a transport
error, or an uncacheable response) is **not** cached and degrades silently to the
lettered tile — no retry, no error — so that domain may be retried on a later
mount or session while the toggle stays on (a negative-cache to suppress repeated
failures is planned follow-up work). The **documented fallback-of-record** —
should the primary provider ever become unusable (e.g. a terms-of-service change)
— is the service's **own `/favicon.ico`**, which would leak only to a service you
already subscribe to. That fallback is a *degradation story*, not a second fetch
path shipped today: Google's `t2.gstatic.com/faviconV2` is the sole live provider,
and Subby ships no separate favicon fetcher.

## Renderer security posture

The renderer is treated as untrusted and tightly sandboxed:

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`

The renderer cannot import `fs`, `path`, or `electron`. Its only capability is
the typed `window.subby` bridge exposed by the preload — which forwards solely
through centralized channel constants, never raw strings. All filesystem access
happens in the main process.

## Content Security Policy

A CSP disallows remote origins in two places (defense in depth):

- **`src/index.html`** meta CSP — `default-src 'self'`, `object-src 'none'`, and
  a `connect-src` that permits no remote `http(s)` origins (dev-only `ws:`/`wss:`
  for Vite HMR).
- **`electron/main.ts`** production CSP applied via `onHeadersReceived` —
  `connect-src 'self'`, `object-src 'none'`, no remote origins.

## Error handling never leaks or crashes

Bad data never crashes the app or escapes as an exception across the IPC bridge.
Reads are classified (`missing`/`malformed`/`corrupt`) and recovered; failures
are returned as user-friendly `AppError` values. See
[Storage & Recovery](./storage-and-recovery.md).

## Verification

Privacy and security properties are checked automatically by the test suite
(`tests/privacy.test.ts`, `tests/accessibility.test.tsx`):

- A static scan of `core/`, `electron/`, `src/`, and `shared/` asserts there is
  **no** use of `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`,
  `sendBeacon`, no imports of network modules (`http`/`https`/`net`/`dgram`/
  `dns`/`tls`/`http2`), no HTTP clients, and no telemetry SDKs.
  (The app's own spending *analytics* module is unrelated and not flagged.)
- The meta CSP and production CSP are asserted to block remote origins.
- The storage layer is asserted to use only `node:fs`.

## Beta caveats

- **Unsigned builds.** Beta installers are not code-signed or notarized:
  - macOS: right-click → Open, or
    `xattr -dr com.apple.quarantine /Applications/Subby.app`.
  - Windows: SmartScreen "More info" → "Run anyway".
- Code signing and notarization are planned for the stable release (see
  [`../RELEASE.md`](../RELEASE.md)).
